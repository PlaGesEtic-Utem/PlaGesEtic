Contexto

Cada endpoint protegido pasa por la cadena de middlewares ya definida: autenticación (JWT) → auditoría (registra el intento) → control de acceso por rol y estudio (RBAC) → controlador → seudonimización de la respuesta. El "rol autorizado" de cada fila es el que exige el middleware de RBAC: para los endpoints bajo un id_estudio, el rol se valida junto con la Membresía de Estudio del usuario, no de forma global. Las excepciones son los endpoints de Autenticación y de gestión de Usuarios, que usan el rol global del Usuario (Director, Soporte), porque no dependen de ningún estudio.

Rol global: Director, Soporte Rol en estudio: Investigador Responsable, Asistente de Investigación, Estudiante, Invitado
Supuesto por validar: se asume prefijo de ruta /api/v1 para todos los endpoints (omitido en la tabla por brevedad) y formato de intercambio JSON. A confirmar con el equipo al iniciar la implementación.
