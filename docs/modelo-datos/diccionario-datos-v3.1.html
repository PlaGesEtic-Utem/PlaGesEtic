Contexto

Cambios v3.1 (10/10/2026): identidad.correo_cifrado, identidad.correo_hash e identidad.telefono_cifrado pasan a NOT NULL, según la decisión del 06/10 (ADR-002, D1). La API ya los valida como obligatorios en POST /identidades y el script 02_restricciones_der_v3.sql los exige en la base. No hay otros cambios respecto de v3; el DER v3 sigue vigente.

Esta versión reemplaza al diccionario v2. Agrega el esquema ethics_schema, cifra los datos personales de identidad, corrige la representación legal, e incorpora protocolos y aprobación del CEC, asentimiento, sesiones de investigación, metadatos de archivos, exportaciones con códigos propios y permisos diferenciados por estudio. El resumen de cambios y la trazabilidad con el documento del cliente están en el DER v3, generado desde la misma definición que este diccionario.

identity_schemaÚnico lugar donde vive la identidad real de las personas. Nombre, correo, teléfono y RUT se guardan cifrados (RNF-SEC-01).

Persona real (participante o representante). Datos personales cifrados en reposo.CAMBIA

Pendiente de validación

Por revisar con el equipo:
  • Plazo de eliminación: definir con asesoría jurídica el plazo entre la revocación y el borrado definitivo (Ley 19.628 y la nueva Ley 21.719 de protección de datos personales).
  • Retiro de un estudio: definir con el CEC qué pasa con los datos ya recolectados cuando una persona se retira (se conservan seudonimizados o se eliminan).
  • Gestión de llaves: dónde viven la llave AES y la llave del HMAC (variables de entorno del contenedor, gestor de secretos), y cómo se rotan.
